## Current state: the lobby
A ride-your-bike speed-training lobby (Roblox-simulator genre, original names/art): an asphalt hub with four zones round a crossroads. North: start pad + checkered band, featured premium bikes on glow rings, the World 2 portal. West: bike garage (two tiers of unlock pads). South: pet hatchery (3 egg pedestals) + leaderboards. East: AFK treadmills under a black-hole vortex, free-rewards chest. North of the band is the hill lane (`lobby/lane.js`). `net.js` (Colyseus client; `VITE_SERVER_URL`, else `ws://localhost:2567` in dev, else the Bloxity matchmaker) loads/saves signed-in players' progress, feeds the leaderboard boards and sends pose/loadout; guests and solo play use localStorage. No real store yet: premium products are granted free only in dev builds (`premium()` in `game/state.js`). Saves go to localStorage (`ihc-save-v1`).

Three.js (vanilla, no React) + Vite + Rapier (`@dimforge/rapier3d-compat`, wasm inlined; `main.js` awaits its init at top level, hence `build.target: 'es2022'`). Everything is procedural (canvas textures); the only imported model is the Bloxity base rig `public/avatars/player.glb`. Font: Fredoka (loaded in `index.html`).

- `npm run dev` / `npm run build`. `VITE_DEV_MODE=true` (see `.env.example`) skips the Bloxity SDK/CDN. Deploy: `.github/workflows/deploy.yml` uploads `dist/` to Bloxity Hosting (main = prod, dev = dev channel).
- All tunables are in `src/config.js` (the rest of `src/` holds no theme values). It now has: identity (`GAME_SLUG`, `GAME_TITLE`, `DEV_MODE`), the lobby layout (`LOBBY`, `SPAWN`, `SPAWN_FACING`), the game catalogs and `ECONOMY`, `MODES`, `PHYSICS`, `PLAYER_DIMS`, the look (`RENDER`, `FOG`, `TIME_OF_DAY`, `LIGHT`, `CHARACTER_COLORS`, `MATERIAL_PBR`, `GRAPHICS_PRESETS`, `BLOOM`, `NEON`, `graphicsPreset`), `TOUCH`, `CAMERA`, `SETTINGS`, and the rig (`RIG*`, `PROPORTIONS`, `ANIM`).
- All Bloxity SDK calls go through `src/bloxity.js` and must never throw (SDK may be blocked). It handles init/loading steps, auth (user/guest), settings (`graphics_quality`, `camera_sensitivity`, `show_fps`, `fullscreen`), avatar + proportion change events, the portal `respawn_request` event, the avatar customizer, and the matchmaker helpers the future net layer needs (`resolveServerEndpoint`, `locateRoom`, `updateRoom`).

## Files (`src/`)
- `main.js`: boot order = Bloxity SDK -> renderer -> Rapier -> lighting, lobby ground, particle pools, zones, player body -> rider (avatar on the equipped bike, swaps in when ready), pets, NPC riders -> HUD -> loop (physics, triggers + training, rider, pets, NPCs, zones, particles, HUD, camera, lighting, bloom render). `__game` (dev only) exposes `player`, `scene`, `renderer`, `camera`, `postfx`, `bodies`, `toggleMode`, `teleport(x, y, z, facing)` (facing `Math.PI` = north, -Z).
- **Player**: `player.js` kinematic capsule + Rapier `KinematicCharacterController` (autostep, slopes, snap-to-ground, pushes dynamic bodies), own gravity/jump (coyote time + buffer). Feet position is `player.position`; `player.renderPosition` is interpolated for drawing. Falling below `PHYSICS.killY` respawns. `camera.js` third-person chase cam (boom, wheel zoom, wall clearance via `segmentClear`, speed FOV) and first person at the inner zoom end; `modes.js` `character` (avatar visible) / `player` (first person, avatar hidden), V toggles. `input.js` keyboard / mouse / pointer lock into `inputState`; `touch.js` + `touch.css` touch controls.
- `avatar/`: `character.js` (player.glb or procedural fallback), `loader.js` (Bloxity cosmetics + proportions from the CDN, `cdn.js`), `rig.js` + `animator.js` (procedural idle/run/airborne/landing; tunables in `ANIM`).
- **Physics**: `physics.js` Rapier world, fixed 60 Hz step with an accumulator; dynamic meshes bound via `bindMesh`/`addDynamic` are interpolated between ticks. Static geometry uses `addFixed` / `addFixedBoxFor`. `segmentClear` is the camera's ray against static colliders only.
- **Ground**: `world.js` `createWorld(scene)`: asphalt hub, raised grass islands with white curbs (orthogonal polygons, trimesh colliders), yellow dashes, START decal + checkered band, terraced voxel cliffs (instanced, rings of dirt then stone, lime caps), instanced trees/tufts/rocks/flowers, clouds, invisible boundary walls. Layout numbers are `LOBBY` in config. `lobby/materials.js` `studMat(color)`: studded plastic, world-space triplanar UVs (works on instanced/stretched boxes).
- **Zones**: `lobby/zones.js` `buildZones(scene, pools)` builds all four zones and returns `{ triggers, npcSpots, boulder(), update }`; a trigger is `{ test(x,z), prompt() -> {text, action}|null, afk?() -> mult, enter?() }`, checked each frame in main.js. Models: `lobby/bikes.js` (`buildBike(def)` 7 styles, `spinWheels`; `userData.seat/bars/pegs/wheels`), `lobby/pets.js` (`buildPet`, `animatePet`, `buildEgg`), `lobby/props.js` (treadmill with scrolling belt, chest with hinged lid, leaderboard tower with `redraw(rows)`, pedestal). `lobby/fx.js`: CPU particle pools (HDR colours, bloom), `glowRing`.
- **Multipliers**: Speed gains x `multiplier()` = rebirths (`rebirthMult`, +`ECONOMY.rebirthBonus` each) x equipped trail (`TRAILS[].mult`) x equipped pets (product of `PETS[].mult`). Levels are capped at `maxLevel()` (= the rebirth level, `rebirthBaseLevel` + `rebirthLevelStep` per rebirth) until you rebirth; Skip Rebirth (premium) adds a rebirth and keeps level/speed. Trails are owned (`ownedTrails`, bought with wins or gems, or prizes: `prize: 'daily' | 'spin'`); pets have `petSlots` / `petStorage` caps (`PET_LIMITS`). Prize bikes (`PRIZE_BIKES`) come from the wheel or Day 7.
- **Game**: `game/state.js` owns progress + every rule (training, levels, wins, rebirth, bikes, pets/eggs, trails, chest/daily/spin, boosts) with `on(event)`; `game/rider.js` avatar seated on the bike (animator 'ride' state, `ANIM.ride`: tuck, hang into corners, squat on landings, up on the pegs in the air) inside lean -> slope pitch (follows the ground under the tyres / the flight arc) -> rear-tyre pivot (launch wheelie, throttle squat, landing dive) -> suspension body (spring bounce, engine shake); particles: throttle-scaled exhaust, tyre dust (asphalt grey / lane orange via `ground`), drift + wheelspin smoke, landing dust ring + grit, launch burst, speed motes, backfire flames on the engine's `onEngine` pop/shift events (`rider.fx`); `fx: 'full'` for the player, 'lite' for remotes; exposes `slip` / `airborne` for the engine sound; tunables in `RIDE`; trail ribbon; `game/petpack.js` equipped pets following. Catalogs (`BIKES`, `FEATURED_BIKES`, `PETS`, `EGGS`, `TREADMILLS`, `TRAILS`, `ECONOMY`, `DAILY_REWARDS`, `SPIN`) are in config.
- **Hill lane**: `lobby/lane.js` (`LANE` in config): slope segments that steepen toward the top (`heightAt(s)`, `angleAt(s)`, s = m up from the band), floor strip + trimesh collider, terraced walls, safe caves on alternating sides (gaps grow) each with a `+N Wins / Return` pad, a summit pad, boulders (4 looks in `BOULDER_LOOKS`, half buried by `LANE.boulder.sink` so they fill the lane, spawn at the top, roll down, flatten anyone on the open lane, shatter at the band); each carries its own speed sign (VERY SLOW..VERY FAST, the face gets angrier) from the mode cycle, NPC riders hopping cave to cave. `lane.rule` is `player.moveRule` (player.js): speed from the Speed stat (`rideMax`/`rideCap` in state.js, capped by Custom Speed), uphill drag. Nothing ever stops the bike: `needAt(s)` is the MAX for full speed uphill (`LANE.need.caves`, linear between caves); below it the bike climbs slower (x MAX/need, at least `need.minUp`), so a weak bike just spends longer among the boulders. The summit dash (`LANE.dash`) is the real goal: once the player rides out above the last cave (`dashFrom`), the next boulder comes exactly `dash.every` s later (and every `dash.every` s while they stay; `rule()` records the player in `rider` for `update()`), and the slope above is set so a sprinting bike at MAX `dash.max` passes the spawn spot (`dashTo`) just in time. Hill training: riding on the lane earns Speed x `trainAt(s, max)` (`LANE.train`, per cave, passed to `train({ hill })` from main.js), counted only up to `fullSpeedS(max)`, so riding laps in your highest full-speed cave beats the treadmills, but dodging higher with a weak bike doesn't train faster. Each cave sign reads `MAX N · xM SPEED`, the summit `DASH! MAX N`, and the HUD shows `NEXT: N (Cave k | Summit)` under MAX (`nextGoal`). The whole economy (bike/trail/egg prices, xp curve, cave wins, needs, train values, dash) is paced with a simulator so a perfect player who never pays reaches the dash MAX in ~5 h+; retune them together, not alone. main.js runs crush (`player.frozen`, squash, respawn at the start pad), pad claims (`addWins`, `winSplash`) and camera shake; `game/popups.js` draws the "+216" speed popups and the win splash.
- **Audio**: `audio/` (all synthesized WebAudio): `core.js`/`synth.js` (buses, reverb, voices), `engine.js` (AudioWorklet bike engine; gear-change clunk, launch tyre chirp, tyre squeal from `slip`, rev flare + road noise drop in the `air` and a bog on touchdown; `onEngine(fn)` emits 'pop' / 'shift' / 'launch' for the visuals), `boulders.js` (rumble loops), `ambience.js` (wind by altitude, birds), `music.js` (generative background music, B key or the touch music button in the top-right corner: warm pad/bass/felt-mallet melody/harp/hand drums under a 3.2 kHz ceiling, motif-based melody, new key + progressions every 32 bars, energy and layers rise with altitude via `setAltitude`, own `A.music` bus that ducks less than the world, B toggles, persisted in `ihc.music`), `sfx.js` one-shots, `hooks.js` (`installAudioHooks()`: state events, HUD clicks/panels/hatch/spin, M mute, B music). Gameplay calls go through `game/audioBridge.js` (`audio.crush?.()` etc.), filled in main.js. Tunables: `AUDIO` in config.
- **New-player intro**: `game/intro.js` (+ `intro.css`, tunables `INTRO` in config) plays a ~20 s film before the first game, with the player's own rider: crane over the band, riding up the lane, a scripted boulder (`lane.cinematic(s, v, kind, mode)`, constant speed so the chase is timed; `lane.clear()` on skip), turn and flee, flattened, then lying flat at the spawn, springing up while the camera orbits behind and blends into the chase cam. Letterbox bars, captions per shot (`INTRO.captions`), Skip button + Enter; the HUD and touch controls hide (`body.intro-on`). main.js runs `runIntro` instead of the game loop meanwhile (no physics/input/training; random boulders held; the film is held on frame 0 under the loading screen). Shown once per account: `introSeen` is in the server save (`SAVED_KEYS`, backend `sanitize.ts`; `markIntroSeen()` in state.js sets it on finish or skip). The loading screen waits up to `INTRO.waitForSave` s (wall clock) for the save answer: `progress` with `introSeen` (or more than `INTRO.veteranPlayed` s played, accounts from before the intro) skips it, `noProgress` for an account plays it; guests (never saved) and no answer in time fall back to the browser flag `localStorage` `ihc.introSeen`. A save that lands mid-film stops it. Dev: `?intro=1` forces it, `?intro=0` / `?tp` / `?boulder` / `?squash` turn it off; `__game.intro()?.shot` and `__game.pause(bool)` help grab frames.
- Dev URL params also: `&boulder=s` drops a boulder s m up the lane, `&squash=1` flattens the player, `&warm=N` (with `&boulder`) fast-forwards the hill N frames for headless screenshots.
- **HUD**: `hud/hud.js` `createHud()` (+ `panels.js`, `icons.js`, `hud.css`): wins/speed/level, zone buttons and all panels (Shop, Rebirth, Trails, Pets, Worlds, Inventory, Daily, Custom Speed, gem shop), toasts, hatch reveal, level-up banner; handles the E key for trigger prompts itself. The Daily, Rebirth, Trails, Pets and Worlds panels use the studded card look (`studs: true` in their panel def: coloured studded header, red X, white studded body); Pets has header chips with [+] (`onChip`), a selected-pet side panel, Equip Best / Unequip All / Delete (two taps). `hud/eggs.js` is the egg popup (shown while standing at a pedestal: the egg trigger's prompt is `{ egg: id }`): 3 x 2 pets with chances, cost, E Open / R x3 Open / Q Auto (its keys are captured before input.js, so R does not respawn there). `hud/prizeart.js` holds the shared SVG art (shoe, trophy pile, trails, bikes, world banners). `hud/spinwheel.js` is the full-screen spin wheel (lava rim, crystal pointer, `Spin (N)` + free-spin clock, spin packs, red X; the rest of the HUD and the touch controls hide while it is up). Spins are banked (`state.spins`; one free spin per `SPIN.freeEvery` s of visible play, `state.spinTimer`), slices are weighted by `chance`, and the wheel can award spin-only items (`SPIN_BIKES`, trails with `spin: true`, owned via `ownedBikes` / `ownedTrails`).
- Dev URL params (dev builds only): `?tp=x,z,facingDeg&zoom=notches&orbit=deg` place the player/camera for screenshots.
- **Sky and light**: `lighting.js` sky shader, stars, PMREM environment, shadowed sun following the player, fog, day/night blend (N). `addLamp` and `setMoods(sky)` are unused hooks. `postfx.js` bloom (EffectComposer: HDR half-float render -> UnrealBloomPass -> OutputPass), on for the High/Ultra presets only (`BLOOM`; threshold 2.0 so sunlit surfaces never bloom).
- **Materials and textures**: `textures.js` canvas painters (cracked sand, water ripples, grass/tiles/crates/planks, outlined text, soft dots, sparkles, ...) and `toTexture` / `mulberry32`. `propkit.js` shared prop helpers: `std`, `glow`, `neon(color, k)` (unlit, HDR-bright with bloom; switched by `setNeonBloom`), `put`, `solidBox` / `solidPole` colliders, `label` (outlined text sprite, repainted once Fredoka loads). `bake.js` merges a Group's static meshes to one mesh per material (draw-call saver; unused so far).
- Controls: WASD/arrows, Shift sprint, Space jump, mouse look (click grabs the cursor = pointer lock, Esc releases it, then Esc opens the portal menu), wheel zoom, V mode, N day/night, R respawn, M mute, B music on/off. Never bind P (CrazyGames: Boxity's pause menu).

## Mobile & responsive (required for every change)
The game must play on phones and tablets (portrait and landscape) as well as desktop. Treat a feature as unfinished until it works on touch and on a small screen.
- **Input**: every action needs a touch path, not just a key. Use Pointer Events (`pointerdown/move/up`, check `e.pointerType`), never mouse-only events. Layout (implemented in `src/touch.js`): left-thumb virtual joystick -> `inputState.move`, right-side drag -> `inputState.look`, on-screen buttons for jump/sprint/mode/etc., pinch -> `inputState.zoom`. Everything still feeds `inputState` in `src/input.js` so game code stays input-agnostic. Pointer lock does not exist on touch; never rely on it.
- **Detection**: decide touch UI with `matchMedia('(pointer: coarse)')` / `navigator.maxTouchPoints`, not the user agent. Show touch controls only on coarse pointers; a device can have both.
- **Layout/UI**: HUD and menus use relative units (`%`, `vw/vh`, `dvh`, `clamp()`) and flexbox/grid, no fixed pixel layouts. Tap targets >= 44px. Respect notches with `env(safe-area-inset-*)` (viewport already has `viewport-fit=cover`). Text readable at 360px width. No hover-only interactions. Add `touch-action: none` on the canvas and game controls so the browser does not scroll/zoom.
- **Resize/orientation**: anything sized to the screen (camera aspect, renderer, HUD) must react to `resize` (covers orientation changes). Use `visualViewport` where the on-screen keyboard or browser bars matter.
- **Performance**: mobile GPUs are weak. Respect the `graphics_quality` presets in `src/config.js` (cap DPR, shadow map size, draw distance); default to a lower preset on coarse-pointer devices. Avoid per-frame allocations; keep draw calls and texture sizes low.
- **Testing**: check every UI/input change at a phone viewport (e.g. 375x812 and landscape 812x375) with touch emulation, plus desktop, before calling it done.

## Bloxity integration (see BLOXITY_CODE_METADATA.md)
